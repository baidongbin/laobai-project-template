# 从 Lite 逐步升级到 Standard

不必整体切换。两档是文档拆分程度不同的初始化预设，不是两套需要同时存在的项目体系。

多服务、多技术栈或并行协作的进一步组织方式见 [大型项目扩展指南](large-projects.md)，不需要切换到第三套预设。

迁移前按 [项目选择](project-options.md) 沿用已确认设置；只有新增或冲突项才询问。升级不自动启用基线、加入打包或改变 Git 策略。

## 什么时候拆分

当某类内容需要频繁独立读取或维护，再从现有文件移动出去；不按文件行数机械升级，也不因一个复杂任务就扩建整套目录。

| 当前内容 | 拆分后的唯一权威位置 | 原位置保留什么 |
|---|---|---|
| README 中详细环境、运行、调试、构建 | `docs/development.md` | 保留最短快速开始步骤，详细选项与排错改为链接 |
| README 中测试策略、命令、验收方式 | `docs/testing.md` | 直接入口链接 |
| 已启用的 README 文档核对状态 | `docs/README.md` 的同名章节 | 保留原 `doc-check` 锚点和直达链接，移动原基线、范围与缺口 |
| README 项目状态需要独立维护 | `docs/roadmap.md` | 保留当前概况和直达链接，不复制进度正文 |
| 简单导航难以覆盖实际文档 | `docs/README.md` | AGENTS 仍保留常见任务的直接入口 |
| 产品说明中的详细能力规则 | `docs/specs/<capability>.md` | 能力概述与链接，保留已被引用的规则编号 |
| 架构说明中的重要长期取舍 | `docs/decisions/<id>-<decision>.md` | 当前约束、结论及决策链接 |
| 路线图无法容纳的版本演进设计 | `docs/versions/<version>/` | 阶段目标与版本入口 |

参考 [Standard 模板](../templates/standard/README.md) 与 [扩展说明](../extensions/README.md)，但不要用空模板覆盖已经写好的 Lite 内容。

## 迁移步骤

先检查工作区、确认迁移范围，保留已有修改。逐项把实际内容移动到目标文档，不复制第二套详细正文。README 保留必要的最短使用命令，命令变化时与开发说明同步核对。新增文档从真实内容出发，未确认部分继续保留草稿标识。

根 README 原有 `development`、`verification` 锚点可能已经被任务引用：迁移后可先保留原锚点，在其下放新文件链接，同时逐步修复引用。不要在移动章节时静默破坏旧任务的导航。

AGENTS 中的开发、验证入口及已启用的文档核对入口改为新文档的直接链接。未启用基线时不建立核对章节。迁移核对记录时重算相对路径，不因文件拆分刷新基线或抹去待核对项。只有引入完整文档导航后，才把 Lite 的详细状态约定移到该导航；AGENTS 保留必要边界与链接，不重复维护两份定义。

若迁移决定清理旧文件，先遵守项目权限和文件安全约定；默认不删除任务历史或替换未提交内容。项目中不要同时维护 `lite/` 与 `standard/` 两个权威文档区。

## 迁移验收

确认一个主题只有一份权威正文，所有相对链接和已使用的锚点仍可到达。产品、架构等已有路径和任务 ID 保持稳定；文档反映实际实现，不把拆分当作功能发布。

用全新会话重复 [只读接入验收](tool-access.md#smoke)。这项验证仍应在实际工具中执行，本模板包不声称已经完成用户项目迁移。
