# 初始化、接入与更新时的项目选择

本指南只供处理模板的 Agent 使用，不复制到目标项目，不作为日常开发的询问流程。Lite 和 Standard 决定文档拆分程度；以下三项独立选择，不新增模板档位或配置文件。

## 先识别，再集中确认

先读取用户当前指令、目标项目已有规则及已明确的长期偏好。已有选择继续沿用，不因模板更新重新询问；临时“不提交／不推送”不改变项目长期策略。

| 场景 | 处理方式 |
|---|---|
| 新项目初始化 | 对尚未明确的三项给出推荐，集中确认一次 |
| 已有项目首次接入 | 保留已有策略和实现，只询问缺失或冲突项 |
| 模板更新或 Lite 升级 | 沿用已选策略，只询问新增选项或实质策略变化 |
| 日常开发 | 执行目标项目的最终规则，不重新运行本指南 |

只有未知项才询问；三项都已明确时直接执行并说明采用的选择。推荐不等于授权，用户尚未回答时继续不依赖选择的检查，保留有关文件，不擅自启用或禁用选项。

## 三项选择与落位

| 选择 | 建议依据 | 目标项目中的结果 |
|---|---|---|
| 文档核对基线：启用／不启用 | 普通小项目可不启用；长期维护、文档易漂移或多 Agent 接续频繁时建议启用，不仅按项目大小判断 | 启用时在 Lite README 或 Standard docs/README 保留唯一核对入口及 AGENTS 核对规则；不启用时仍同步文档并说明未知项 |
| 源码 ZIP 打包：加入／不加入 | 需要上传源码给 AI 或分享时加入；已有源码导出方案时优先复用 | 加入根级 `package.sh`、对应使用说明及根 ZIP 忽略规则；不加入时不带模板脚本和打包章节 |
| Git 策略：按明确指令／自动提交／自动提交并推送 | 按用户习惯和项目流程建议；无依据时建议按明确指令，已有 PR、受保护分支或发布约定优先保留 | 将最终 commit、push 策略直接写入 AGENTS 的“提交与推送”，不保留候选菜单 |

询问示例（按项目情况填写，不重复询问已知项）：

> 根据这个项目的用途，建议文档基线暂不启用、加入源码 ZIP 打包、按任务单元自动提交但推送需明确指令。是否采用？可以单独调整任意一项。

未来日常开发遇到范围外操作、身份不明、远端分歧或部署风险时，仍执行项目已有安全规则；“不重复询问选项”不等于放弃授权边界。

## 填充预设材料

两档源码各保留一份可直接使用的 `package.sh` 和可选段落，方便 Agent 按选择取用；这些材料不是目标项目必需文件。默认核心为 Lite 六个文件、Standard 九个文件，分别含四份和七份 Markdown。

模板中的 `<!-- OPTIONAL:baseline:BEGIN -->`／`END` 和 `<!-- OPTIONAL:package:BEGIN -->`／`END` 标明待处理范围：

- 启用时保留块内正文，去掉标记；不启用时连同块内正文一起省略。
- 逐一处理 AGENTS 导航、核对规则、README 及 Standard 开发说明中的对应块，避免残留链接；目标项目不得留下这些标记。
- 不加入打包时不复制模板 `package.sh`。模板 `.gitignore` 的 `/*.zip` 仅在需要此打包方案时保留；已有项目的忽略规则不自动删除。
- 已明确不启用基线时，在 AGENTS 的文档同步章节简记“本项目随改动同步文档，不维护文档提交基线”；已明确不加入打包时，在 README 开发说明简记“未启用独立源码 ZIP 打包”，或说明已有源码导出方式。这样更新时能识别明确的关闭选择，不把缺少文件当成尚未询问。启用时由实际入口和规则表达选择，不另存重复清单。
- Git 默认两句为“仅在用户明确要求提交／推送时执行”。已确认自动提交时，把提交策略替换为“任务单元完成、必要验证通过且最终 diff 无冲突时，自动精确提交本次内容”。已确认自动推送时，把推送策略替换为“本次交付收尾时，按下方检查条件自动推送已获授权的提交，可统一推送多个已完成提交”。其余质量和安全规则保留。
- 已有项目的自定义 Git 策略原位保留，不强制转换成上述三种；新项目填写后也只保留最终规则。

`package.sh` 导出已提交源码，不替代 npm、Docker 等业务构建。已有同名脚本时核实用途，优先复用；确需另取名字时确认路径并同步用法，不覆盖已有构建脚本。

已启用基线但没有实际核对时保持“未核对”。不启用文档基线也不删除任务接续提交、版本设计基线或历史发布标识，它们分别承担任务与历史追溯职责。

## 更新与关闭已有选项

更新只合并实际相关的新规则，不用整份新模板覆盖项目内容。旧项目没有本指南或标记，不代表尚未选择；以现有规则、脚本和有效记录为依据。

启用新选项前确认意图。明确要求关闭已启用选项时，先检查现有引用及历史记录：不自动删除脚本、核对证据或其他用户内容；提出最小调整并按授权处理，旧锚点有引用时保留必要跳转。选择结果写回原有权威位置，不建立第二套配置或选择记录。

交付前检查：目标项目只保留确定规则，没有选项菜单或模板标记；未选脚本及其入口没有被引入；实际链接可达；已有授权、历史与未提交修改未被覆盖。报告本次采用或保留的选择和实际验证，不把模板检查当成真实工具验收。
