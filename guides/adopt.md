# 已有项目接入

接入以真实代码和已有有效文档为依据。目录不必与模板完全相同，业务代码不为模板搬家。提供目标目录、所选预设和已授权范围后，在 AI 工具中打开目标项目，替换以下路径和预设后发送。路径必须是 Agent 能实际读取的位置；模板仓库仅供参考，修改对象是目标项目。

先按 [项目选择](project-options.md) 识别已有决定，只对未确定选项及尚未决定的实质差异集中确认。选择写入目标项目后，日常开发不重复询问。

```text
模板仓库：<模板仓库的绝对路径>
目标项目：<目标项目的绝对路径>
预设：Lite（需要时改为 Standard）

请按指定的 Lite 或 Standard 预设，增量整理当前项目的协作文档。
先读取模板仓库 guides/project-options.md，比较项目已有方式与新版；只对未确定选项及尚未决定的实质差异集中询问保留还是切换，已一致或此前对同一差异明确选择过的不得重复询问。
先确认工作目录、项目规则、Git 分支和未提交改动；仅检查任务相关代码、配置、测试和文档。
检查已有正文能否回答用途、当前进度、开发和核对范围；等价内容原位复用，不只按文件名判断，不为统一名字迁移。
列出现有内容与模板职责的对应关系，然后在已授权范围内逐文件合并，不用空模板覆盖现有正文。
README 保存使用入口，产品文档保存目标与规则，架构文档保存当前实现；开发与测试说明按预设和实际规模组织。
保留业务约束、任务状态、稳定编号和授权边界；已有机制与新版存在实质差异时，先列出原方式、新方式和影响，不机械保留或直接替换。
已有 Git 策略与新版不一致时按项目选择指南询问保留或切换；已明确选择或一致时沿用，没有既定策略时集中确认，目标 AGENTS 只保留最终规则，不携带询问菜单或 OPTIONAL 标记。
本次接入指令中的不提交／不推送仅约束本轮，不写成项目长期限制。
只有本次授权包含合并或迁移时才移动重复正文，原处保留必要说明和链接；否则报告重复位置。
对尚未明确决定的实质差异集中询问，不限于无法兼容的冲突；等待决定期间保留有关内容，继续不受影响的部分。
按已确认选择检查源码 ZIP 打包：选择加入且缺失时接入模板脚本；已有脚本行为有实质差异时说明并询问保留还是采用新版，不直接替换；未选择时不引入模板脚本或打包入口。
不为匹配模板重排源码，不导入全部扩展，不要求安装个人 Skill。
工程命令从实际配置核对；执行与文档修改相关的安全检查，未运行的业务检查明确标为未验证。
修复受影响的链接和锚点；不把接入模板当成功能完成或发布。
采用模板打包方案时告知打包只归档 HEAD，输出到项目根目录，同名替换且成功后仅保留本项目最新包；接入验证在隔离样例中进行，不在接入时生成项目 ZIP。
仅启用文档基线时检查唯一核对入口；已有有效位置原位复用，缺失时才默认 Lite 的 README 或 Standard 的 docs/README。
已有 pending/verified 等核对状态与新版三项记录方式不同时，核实字段含义及依赖，说明差异并询问保留还是简化；不得未经决定新增、沿袭或删除该机制。
采用新机制不等于迁移入口；路径迁移另说明必要性、影响并取得对应授权。无可用基线保持“未核对”；可信基线、覆盖和累计缺口保留，不因接入或迁移自动推进。
报告修改文件、保留和合并的内容、实际验证与剩余问题。
不自动删除文件、初始化 Git、commit、push、安装依赖或部署。
```

两档逐步拆分遵循 [升级指南](lite-to-standard.md)。接入后执行 [工具只读验收](tool-access.md#smoke)；有未完成任务时还需检查接续记录与当前代码状态的差异。
