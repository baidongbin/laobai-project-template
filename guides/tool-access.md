# 工具接入与只读验收

公共规则只在项目根 `AGENTS.md` 维护，公共项目资料只在 README 与 docs 中维护。工具专属入口仅负责接入，不复制产品、架构和进度全文。

## 接入方式

| 工具 | 本包采用的方式 | 官方依据 |
|---|---|---|
| Codex | 项目根目录的 `AGENTS.md` | 官方指引说明会在开始工作前发现并读取指令文件，具体范围与当前工作目录有关。[1] |
| Cursor | 项目根目录的 `AGENTS.md` | 官方规则文档提供它作为简单项目指令入口。[2] |
| Kimi Code | 项目根目录的 `AGENTS.md` | 官方文档将该文件用于项目说明与指引。[3] |
| Claude Code | 根 `CLAUDE.md` 使用 `@AGENTS.md` | 官方说明 Claude Code 读取 CLAUDE.md，可通过导入复用 AGENTS.md。[4] |

仅提供根入口，不假定各工具的子目录规则、优先级与全局配置完全一致。确有局部规则需求时再按工具实际能力配置。本包不修改个人全局设置、权限、模型参数或 Skills 安装位置。

## Claude Code 适配

将 [CLAUDE 模板](../adapters/claude/CLAUDE.md.template) 复制到项目根目录，命名为 `CLAUDE.md`，内容为：

```markdown
@AGENTS.md
```

如果项目已有 CLAUDE.md，先保留并检查其内容，在适当位置合并这行导入；不要覆盖有效规则或造成重复导入。这里只导入小型入口，不把整个 docs 目录通过导入加载。

Claude Code 官方说明导入内容也会在会话开始时进入上下文，因此拆成多个导入文件不自动减少启动读取量。[4]

## 接入后的约束

按具体项目确认根目录与工具加载情况。存在文件不证明工具已经加载；引用文档也不表示会递归读取其所有链接。避免从模板包根目录同时把两套预设当作一个业务项目使用。

## 新会话只读验收

在真实项目完成模板填充后，从项目根目录打开新的工具会话，使用下面的指令。它不授权改文件或启动服务。

```text
请只读检查这个项目的 AI 协作入口，不修改任何文件，不运行构建、测试或服务。

说明你实际读取了哪些项目规则与文档；不能把文件存在当成已经加载。
请直接定位：产品范围、当前实现架构、开发命令和验证入口。
如果我已经指定任务，只读取该任务及必要依据；没有指定任务时不要自行选择进行中的任务。
区分当前实现、目标设计、历史快照与未填写的占位内容。
给出本次定位所依据的文件或章节，以及仍需要确认的信息。
不要遍历全部历史版本、归档任务或无关文档，也不要把占位命令描述为可执行。
```

验收时观察：是否找到正确入口、避免不必要的全库读取、准确区分事实与目标、没有执行未授权操作。不能仅凭 Agent 自报“已加载”认定成功；应结合工具可见的加载信息或读取记录、引用文件内容进行核对。

工具实际加载效果与业务运行仍需在本机验证。当前源码的可重复检查范围与命令见 [开发与验证](../README.md#development)。历史检查结果不代表后续源码修改已经验证。

## 跨会话接续验收

在真实项目已有未完成任务时，另开新会话并指定任务路径，使用以下指令：

```text
只读检查我指定的任务记录，不修改文件或启动服务。
比较最近接续记录与当前分支、提交和未提交改动，指出哪些任务信息仍可信、哪些需要重新核实。
直接定位相关代码与验收入口，给出下一步具体动作和必要验证。
没有记录基线时明确说明，不假定工作区没有变化。
不要扫描无关归档，也不要自行实施。
```

观察实际读取记录及相关差异，确认工具没有照搬旧进度。可在隔离样例中改变一处任务相关代码，再验证新会话能否发现；不为验收改动真实项目业务。该场景需在实际工具中执行，结构检查不能替代。
