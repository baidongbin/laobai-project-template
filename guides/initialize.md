# 新项目初始化

默认选择 Lite，需要独立开发与测试说明时选择 Standard。先确认目标目录和产品目标，再按已确认选择将所选预设的核心文件和必要可选材料（含点文件）放入空目标目录。目标非空时改用 [已有项目接入](adopt.md)。本指南与扩展库不默认复制进业务项目。

在 AI 工具中打开目标项目，替换下面的路径、预设和产品目标后发送给 Agent。可以让 Agent 完成复制，无需手动预置文件；若已复制则核对并填充，避免重复覆盖。

先按 [项目选择](project-options.md) 识别已有决定，只对缺失或冲突项集中确认。选择写入目标项目后，日常开发不重复询问。

```text
模板仓库：<模板仓库的绝对路径>
目标项目：<目标项目的绝对路径>
预设：Lite（需要时改为 Standard）
项目目标：<用户、核心场景、范围和已确认约束>

请根据我指定的目标目录、模板预设和产品目标初始化项目协作文档。
先读取模板仓库 guides/project-options.md，沿用已明确偏好，只集中询问未确定的选项；等待回答期间继续不依赖选择的检查，不改动依赖选择的内容。
先检查目标目录及现有文件，存在内容时不得覆盖，改为逐文件增量接入。
复制所选预设的核心文件，包含 .gitignore、.editorconfig；package.sh 和文档基线按已确认选择取用，不复制另一档或全部扩展。
按项目选择指南处理 OPTIONAL 块和 Git 策略，去掉标记，只留下最终规则，不把询问菜单写入目标 AGENTS。
读取目标项目 AGENTS.md，依据已确认目标和实际文件填写 README、产品与架构说明。
没有代码时明确写尚未实现，不虚构依赖、命令、代码入口、测试或完成状态。
未知内容保留待确认并说明影响；可选且无实际用途的章节删除。
有需要时按工具接入指南添加薄入口；不覆盖既有工具配置。
仅选择源码 ZIP 打包时，告知打包只归档 HEAD，输出到项目根目录，同名替换且成功后仅保留本项目最新包；本次初始化不执行打包。
仅启用文档基线时建立统一入口：文档核对状态位于 Lite 的 README 或 Standard 的 docs/README；没有实际提交核对就保持“未核对”，不填假基线。
核对文件数量、实际相对链接与内容边界，并报告已知信息和待确认事项。
本任务只授权协作文档、基础配置和打包入口初始化，不授权业务实现、安装依赖、启动服务、创建 Git 仓库、commit、push 或部署。
```

完成后按 [只读接入验收](tool-access.md#smoke) 在新会话中检查。模板状态 `active` 仅表示内容已确认有效，不能代替实现或运行验收。
