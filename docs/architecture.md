# 当前架构

## 组成与边界

本项目为静态模板库与 Python 检查工具，没有业务服务、数据库或安装阶段。根级 `package.sh` 提供固定 Git HEAD 的 ZIP 归档。

| 模块 | 入口 | 职责 |
|---|---|---|
| 两档预设 | [Lite](../templates/lite/README.md)、[Standard](../templates/standard/README.md) | 提供可独立复制的项目文档与配置 |
| 扩展库 | [扩展说明](../extensions/README.md) | 定义扩展模板到业务项目路径的映射 |
| 接入流程 | [初始化](../guides/initialize.md)、[已有项目接入](../guides/adopt.md) | 指导 Agent 填充、合并和核验 |
| 大型项目扩展 | [扩展指南](../guides/large-projects.md) | 提供扩展指南及模块规则、领域架构、环境模板；跨模块任务复用既有计划，不提供第三档预设 |
| 工具适配 | [工具接入](../guides/tool-access.md) | 根级公共入口与 Claude 导入 |
| 检查器 | [validate.py](../scripts/validate.py) | 只读结构、一致性与模拟落位检查 |
| 回归验证 | [test_validate.py](../tests/test_validate.py) | 在临时副本注入错误，验证失败识别 |

## 数据与执行流程

检查器读取维护源码 → 核对文件集合和公共规则 → 将扩展映射到内存中的目标项目 → 检查本地链接、显式锚点、元信息和 ID → 输出摘要及失败详情。

两档默认落位分别检查；全扩展模拟只用于验证路径，不意味着业务项目应全部安装。外部资料 URL 不由本检查器访问，工具实际加载由接入验收单独验证。

## 重要取舍

- 当前保留两份完整预设，便于直接复制；根级及两档的 `package.sh` 保持一致，用检查器约束公共文件与规则一致，不引入生成器。
- 打包入口仅使用 sh 和 Git，归档范围、同名替换与旧包清理在 [隔离测试](../tests/test_package.py) 中验证；不会为了获得 HEAD 自动提交。
- 扩展模板的相对链接以目标位置为准，不能在源模板目录直接判断其链接失效。
- 使用标准库与简单 front matter 子集，避免为少量固定字段引入 YAML 依赖；检查器遇到不支持的元信息行会报错。
- 初始化和迁移通过明确指令由 Agent 执行，已有文件逐项合并，避免盲目复制覆盖。

## 文档状态与接续

Lite 在根 README、Standard 在 docs/README 统一记录文档核对基线、覆盖范围和待核对内容；AGENTS 给出直接入口及比较、同步、更新规则。该记录不等于文档有效状态或业务验收，不自动解析提交或执行核验。

项目进度默认在 README，有需要再移到 roadmap；产品要求、架构现状、任务实施记录各自维护。迁移保留基线及缺口，不因路径变化推进核对结论。

## 当前限制

尚未完成真实业务项目接入和四种工具的跨会话接续验收。模板不会自动与代码同步，也不强制执行权限控制。Markdown 检查针对本仓库现有行内链接和显式锚点，不支持完整 Markdown 语法或自动标题锚点。
