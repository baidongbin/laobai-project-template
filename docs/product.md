# 产品目标与范围

## 目标

让不同 AI 工具通过少量项目入口，定位可信的项目事实、相关代码和任务接续点，减少每次会话重新理解整个项目的成本。必要代码核验仍然保留，不承诺零读取或自动记忆。

## 使用场景

- 新项目选择 Lite 或 Standard，填入已知目标、实际实现与工程命令。
- 已有项目保留有效内容，按职责边界增量整理文档。
- 中断后换会话或工具，通过任务记录核对代码变化并继续实施。
- 文档复杂度增加时逐项扩展，不重新建立另一套权威资料。

## 核心要求

| 条款 | 要求 | 验收方式 |
|---|---|---|
| REQ-001 | Lite 核心四份 Markdown，Standard 七份；打包与文档基线按已确认选择取用，可选扩展不自动导入 | 检查预设文件集合与独立落位链接 |
| REQ-002 | 共用规则不因预设不同而分叉 | 共用文件及 AGENTS 公共段落一致性检查 |
| REQ-003 | 项目脱离模板仓库后仍可使用 | 模拟独立落位，无模板库路径依赖 |
| REQ-004 | 当前事实、目标设计、历史与验证结果明确区分 | 模板内容审查；目标项目实际填充后复核 |
| REQ-005 | 接续先核对代码状态，再执行具体下一步 | 真实工具的新会话只读接续验收，当前尚未完成 |
| REQ-006 | 已有项目不得被模板静默覆盖 | 接入流程保留有效内容，检查差异及引用 |
| REQ-007 | 启用文档基线时，范围与缺口只在一处汇总；未启用也同步文档并说明未知项 | 入口与迁移规则检查；没有提交时保持未核对 |
| REQ-008 | 初始化、接入与更新集中确认未确定选项及尚未决定的实质机制差异；机制更新与入口迁移分开决定，目标 AGENTS 只留最终规则，日常不反复询问 | 场景指南与目标规则审查；真实交互尚未验收 |

## 范围与非目标

本项目维护模板、薄适配入口、执行指令和必要结构检查。暂不开发 Skill、CLI、自动升级服务、业务框架或多 Agent 调度，也不维护个人全局规则。

工具是否实际加载、文档是否反映目标项目代码、业务是否通过验收，需要在目标项目验证；模板结构通过不能代替这些结论。
