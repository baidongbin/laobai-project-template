# laobai-project-template

老白（LAOBAI）通用 AI 项目模板的独立维护仓库，用于轻量版与标准版模板维护、项目初始化与接入、结构验证及版本演进。

## 项目概览

面向希望在不同 AI 工具之间复用项目上下文、按计划实施任务的开发者。Lite 与 Standard 共用规则，按项目需要选择预设，再逐项扩展；接入后的项目独立维护，无需安装 Skill。

本项目自身采用 Lite 布局。目前已具备模板、接入指南和结构检查，尚未完成真实项目的跨工具接续验收。

## 主要功能

- Lite 四份、Standard 七份 Markdown 核心预设，带基础编辑与忽略配置；源码 ZIP 打包与文档基线按选择取用。
- 按需增加规格、任务计划、版本设计、决策、部署与参考资料，以及模块规则、领域架构和环境隔离模板。
- 新项目初始化、已有项目接入、逐项升级与工具入口适配。
- 仅依赖 Python 标准库的结构检查器及隔离回归测试。

## 快速开始

### 使用前提

使用模板无需安装依赖，准备一个目标项目目录及已明确的项目目标即可。运行维护检查需要 Python 3.9 或更新版本；打包及打包测试还需要 Git 和 sh，Windows 使用 Git Bash/WSL。

### 初始化一个新项目

1. 在 AI 工具中打开目标项目目录，准备本模板仓库的可读路径和项目目标。
2. 复制 [初始化指令](guides/initialize.md)，填写路径与目标；默认选择 Lite。Agent 按 [项目选择](guides/project-options.md) 沿用已明确偏好，只集中询问尚未确定的基线、打包与 Git 策略，再完成取用和填充。
3. 按 [工具接入指南](guides/tool-access.md#smoke) 开启新会话，检查资料定位是否正确。

两档模板源码包含可选材料，并非原样全量复制的最终项目；核心文件分别为六个和九个，加入打包各增加一个脚本。选择只在初始化、接入或更新时确认，日常开发按项目已确定规则执行。本仓库自身保留文档基线、根级打包和自动提交推送策略。

没有实现的内容保持“尚未实现”，不把占位命令当成可执行命令。已有文件的项目使用增量接入流程。

## 使用方式

| 场景 | 做法 |
|---|---|
| 新项目 | 使用 [初始化指令](guides/initialize.md)，默认 Lite |
| 已有项目接入 | 使用 [接入指令](guides/adopt.md)，保留有效内容，逐文件合并 |
| 更新已接入项目的规则 | 使用 [更新指令](guides/update.md)，沿用已确认选择，仅询问新增或冲突项 |
| 需要独立开发、测试说明 | 选择 `templates/standard/`，或按 [升级指南](guides/lite-to-standard.md) 逐项拆分 |
| 增加任务、规格等资料 | 按 [扩展说明](extensions/README.md) 只取需要的模板 |
| 新开发大型项目 | 使用 [新大型项目指令](guides/large-projects.md#new-project)，Standard 底座加首阶段计划 |
| 已有大型项目 | 使用 [已有大型项目指令](guides/large-projects.md#existing-project)，全局入口加单领域试点 |
| 换工具或接续任务 | 按 [工具接入指南](guides/tool-access.md) 核对入口和任务记录 |

## 项目结构

```text
.
├── templates/       # Lite 与 Standard 预设
├── extensions/      # 按需文档扩展
├── adapters/        # 工具入口适配
├── guides/          # 初始化、接入与迁移指南
├── docs/            # 模板项目自身的产品与架构说明
├── scripts/         # 模板检查工具
├── tests/           # 隔离回归测试
├── package.sh       # Git HEAD 打包入口
├── AGENTS.md        # 维护本仓库的协作规则
└── README.md
```

<a id="development"></a>
## 开发与测试

在仓库根目录执行结构检查；需要详细输出时追加 `--verbose`：

```sh
python3 -B scripts/validate.py
```

修改检查器或打包脚本后运行回归测试，测试使用临时目录：

```sh
python3 -B -m unittest discover -s tests -v
```

结构检查覆盖文件集合、共用内容、相对链接、显式锚点、扩展落位、元信息和文件格式，并模拟两档各四种文档基线／打包组合，检查未启用选项的残留入口和可选块格式。它不是通用 Markdown/YAML 解析器，不验证外部 URL、业务命令或工具实际加载。模板修改后应同步受影响的文档并执行相关检查。

## 打包

在项目根目录执行：

```sh
sh package.sh
```

生成根目录下的 `<项目名>-<短HEAD>.zip`，仅包含已提交内容。同名包直接替换，成功后仅保留本项目最新包；归档生成失败时保留旧包；若替换后的旧包清理失败，新包已生成，旧包可能部分保留。首次提交前无法打包。
