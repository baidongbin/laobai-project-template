# 文档导航与约定

已知道要读什么时直接读取对应文件；不要求每次任务经过本页，不递归加载全部关联资料。

## 文档核对状态

- 核对基线：未核对。
- 已核对范围：无；填写实际核对的文档及覆盖内容，不默认代表全项目。
- 待核对内容：初始化后核对项目入口、产品要求的确认依据、当前实现与开发验证说明。

基线填写实际完整提交标识，不写移动分支名或 HEAD。范围描述的是该提交上的核对结果；之后的变化需另行比较。文档有效、代码实现、测试通过和生产验收是不同结论。本节是唯一汇总入口，不在其他文档复制同一份核对记录。

## 可选资料入口

尚未登记。实际创建后，在下面添加“用途、入口、当前状态”，不要列出不存在的链接。

约定位置：`roadmap.md` 管当前状态与路线规划；`specs/` 管长期能力规则；`versions/` 管版本目标和演进设计；`decisions/` 管重要决策理由；`plans/active/` 与 `plans/archive/` 管单次改动过程。

任务文件与版本目录不互相嵌套，以相对链接关联。同一能力可以对应多次任务，不把现行规格埋在历史任务里。

## 文档契约

### 格式与最少字段

入口使用普通 Markdown。知识、任务、版本和决策文档使用 YAML front matter 与 Markdown 正文。元信息是本项目约定，不代表工具会自动解析或强制执行。

| 字段 | 适用范围 | 约定 |
|---|---|---|
| `type` | 非入口资料 | `product`、`architecture`、`development`、`testing`、`roadmap`、`spec`、`plan`、`version`、`design`、`verification`、`decision`、`architecture-snapshot`、`deployment`、`reference` |
| `doc_status` | 非入口资料 | `draft`、`active`、`superseded`、`archived` |
| `id` | 需要稳定引用的规格、任务、决策 | 例如 `SPEC-IMPORT`、`PLAN-001`、`ADR-001`；同一项目内唯一 |
| `task_status` | 任务主记录 | `planned`、`in_progress`、`blocked`、`done`、`cancelled` |
| `version`、`version_status` | 版本主记录 | 项目实际版本标识；状态为 `planned`、`in_progress`、`released`、`cancelled` |
| `baseline_ref` | 版本目标设计 | 实际 tag 或完整提交标识，固定设计出发点 |
| `release_ref` | 发布架构快照 | 与快照对应的实际发布 tag 或提交 |

只有任务主记录保存任务状态，子设计与验证文件不再复制。验证结果在正文记录为“通过／失败／未验证／不适用”，不增加重复的总状态。

`draft`：未确认。`active`：当前有效，不代表功能已实现。`superseded`：已被替代，正文必须链接替代文档。`archived`：历史记录，不作为默认当前依据。

进行中任务通常为 `doc_status: active`。结束后迁入 `plans/archive/`，改为 `archived`，保留真实的 `done` 或 `cancelled`。归档不等于通过验收。

`{{NAME}}` 是占位符；“待填写／待核实／待确认”表示未知，不可当作事实。确认有效前保留 `draft`；不适用的可选段落删除或说明不适用原因。不要写入未经执行的成功结果。

### 关联关系

使用相对当前文件的 Markdown 链接，并写明关系：需求依据、目标设计、当前约束、决策依据、实现位置、验证方式、验证证据或替代关系。

关键规则使用稳定条款号，如 `REQ-IMPORT-003`。引用写“文件链接 + 条款号”，不只依赖会变动的标题锚点。编号不是自动跳转器，文件移动后仍需修复链接。

导航负责发现，任务负责串联直接依据；不要求所有文档双向互链，不复制正文到任务“上下文”里。不存在的可选资料只用普通文字说明，不创建伪链接。

### 当前、目标与历史

当前架构随实际实现更新；版本设计记录固定基线及尚待实现的目标；历史架构优先通过发布 tag 回溯，只有需要当前工作区直接阅读时才另存快照。

当前规格描述已采纳要求，不自动证明代码满足要求。任务必须用实际验证说明符合性。历史快照发布后冻结，不跟随新版本改写；必要勘误须说明依据。

### 同步维护

| 变化 | 应检查的权威文档 |
|---|---|
| 产品范围、业务规则 | 产品说明、受影响规格 |
| 项目进度、阶段或版本目标 | README 当前状态或已建立的路线图、对应版本入口 |
| 模块职责、依赖、数据流 | 当前架构；必要时记录决策 |
| 环境、配置、开发命令 | 开发说明及真实配置示例；涉及快速开始时同步核对 README |
| 测试命令或通过标准 | 测试说明 |
| 任务进度、阻塞、验证结果 | 任务主记录；拆分后证据放验证附件 |
| 文档迁移、归档或替代 | 受影响的入链、出链和导航 |

先同步长期有效内容，再归档任务过程。文件扩展为目录时保持任务 ID，修复路径，不保留两份权威正文。
